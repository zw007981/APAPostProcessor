## 适用场景

`.gitignore` 条目随时间无序堆积，需要整理成统一、可预测的排列。本模板给出唯一确定的排序规则，避免不同 Agent 各排各的。默认处理仓库根目录的 `.gitignore`；若人类指定其他 ignore 文件（如 `.dockerignore`），同一套规则同样适用。

> 本规则只处理**纯条目清单**（每行一个忽略模式，含 `!` 开头的反模式）。若文件中存在注释行（`#` 开头），不要自行发明规则，先停下来向人类确认如何处理。

## 排序规则

1. **最多分四段**，顺序固定：
   1. 普通目录模式（`/` 结尾）
   2. 普通文件/通配模式（其余不以 `!` 开头的条目）
   3. 反模式目录（`!` 开头且去掉 `!` 后以 `/` 结尾）
   4. 反模式文件（`!` 开头的其余条目）

   反模式段永远排在普通模式段之后；某段没有条目时整段省略，不留悬空空行。
2. **段间分隔**：相邻两段之间用**恰好一个空行**分隔；段内不允许出现空行。
3. **段内排序**：按整行 ASCII 字典序排序（等价于先按首字符比较，首字符相同再依次比较后续字符）；反模式条目排序时**忽略 `!` 前缀**，按其后的内容比较。字符顺序参考：`.`(46) < 数字(48-57) < 大写字母(65-90) < `_`(95) < 小写字母(97-122)。
4. **文件结尾**：文件以最后一个条目直接结束，**末尾不保留任何空行/尾随换行符**——最后一个字节是末行条目的最后一个字符，不是 `\n`。

> 规则 4 是有意为之：编辑器中文件末尾不应显示多余空行。代价是 git diff 会显示 `\ No newline at end of file`，这是本规则的既定取舍，不要"顺手"把换行加回去。

## 标准步骤

1. 读取目标文件全文。
2. 检查是否存在 `#` 注释行：若有，停止并向人类确认；若无，继续。
3. 按上述规则分类、排序，一次性重写整个文件。
4. 验证：
   - 各段严格按「普通目录 → 普通文件 → 反模式目录 → 反模式文件」的顺序排列，缺省的段已整段省略；
   - 每段内部严格 ASCII 升序（反模式段忽略 `!` 前缀比较）；
   - 相邻段之间恰好一个空行，段内无空行；
   - 文件末尾无尾随换行（可用 `tail -c 1 .gitignore | od -c` 确认最后一个字节不是 `\n`）。

## 完成标准

文件被重写为「普通目录段 → 普通文件段 → 反模式目录段 → 反模式文件段」的形式（空段省略），相邻段间恰好一个空行，段内 ASCII 升序（反模式忽略 `!` 前缀），末尾无空行；把排序结果展示给人类确认。
